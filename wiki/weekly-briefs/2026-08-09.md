# Trends in the industry
- **Agent permission models shift from manual per-command approval to classifier-gated autonomy.** Anthropic's Claude Code auto mode (default for Pro/Max/Team as of Aug 14) replaces the per-command approval prompt with a real-time classifier that gates tool calls, backed by a controlled study (89% vs. 13.6% human dangerous-command catch rate) and a third-party eval reporting 0/720 successful prompt-injection attempts. Self-hosted-runner and production-hardening posts shipped the same week — this is a coordinated push, not a one-off feature.
- **Cross-vendor packaging standardization arrives for agent extensions.** Agent Plugins v1.0.0 lets one `plugin.json` + `skills/` + `mcp.json` bundle install across ChatGPT, Codex, Cursor, and GitHub Copilot without per-client rewrites. It's a thin envelope over MCP and the separate Agent Skills spec, not a replacement for either, and explicitly ships v1 with no permission model, no secrets mechanism, and no sandboxing — those are named as future work.
- **The coding-agent vendor field widens again.** Meta shipped its first coding agent (Muse Code, beta), positioned on cost rather than capability against Codex and Claude Code. AWS (Kiro Crew, an open-sourced orchestration layer) and Cloudflare (Kitesurf, a stripped-down agent-native browser) also shipped agent-infrastructure plays the same week — every major cloud and lab now has a stake in the stack.
- **"Context engineering" is fragmenting as a term across vendors.** Sierra's new Context Engine product reuses the "context engineering" brand for a business-data/entity-linking/outcome-learning layer, distinct from the prompt-assembly-block sense the term already carries in this wiki (and in Anthropic's usage). *(synthesis)* Expect more vendor collisions on this vocabulary before it settles.
- **Self-improving-agent skepticism gains a second independent data point.** ContinualSkillBench (Peking University/BIGAI) finds that explicit, agent-driven skill maintenance ties pure in-context learning on average, and that weaker models accumulate larger, more fragmented skill libraries than stronger ones — a distinct methodology from, but directionally resonant with, SkillOS's gated-curator counter-evidence already in this wiki.
- **Benchmark movement this week is second-order, not first-order.** *(synthesis)* OSWorld-Verified got a new leader (Qwen3.8-Max, 86.1%) and SWE-bench Verified/Pro kept clustering near their respective ceilings, but neither reflects a benchmark-methodology breakthrough — the more interesting activity is meta-evaluation work (ScrambleToolBench's tool-reuse failure mode, a new "Benchmarking the Benchmarks" LLM-judge framework) questioning what the existing leaderboards actually measure.
