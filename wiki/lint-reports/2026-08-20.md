### Capture Fidelity (raw/)
**Tool bug found in `tools/audit_captures.py` — most of its "broken image ref" output this run is a false positive, not a real capture failure.** Image refs across the corpus are written in three styles: `./assets/...` (resolves correctly), absolute `/home/david/...` paths, and repo-root-relative `raw/research/<topic>/assets/...`. The tool's regex negative-lookahead excludes any ref starting with `/`, so **absolute-path refs are silently never checked** (`ov3d-instance-seg` reports "0 issues" but is actually unverified, not clean — confirmed: its regex is `(?!https?://|data:|javascript:|mailto:|#|/)`). For the repo-root-relative style, the tool does `(md.parent / ref).resolve()` — since `md.parent` is already `raw/research/<topic>/` and `ref` repeats `raw/research/<topic>/assets/...`, the path gets double-joined and wrongly reported broken. Verified independently: `raw/research/language-3d-scene/01-lerf-2303.09553.md` references `raw/research/language-3d-scene/assets/lerf-2303.09553/source.pdf-0-0.png`, which exists on disk but is flagged "broken" by the tool.
