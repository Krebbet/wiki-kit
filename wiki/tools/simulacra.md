# Simulacra

Simulacra is an open-source, modular multi-node ESP32 firmware project (single primary maintainer, forked from and extending `0xXyc/splinter`, GPLv3) that defends against passive RF-based physical tracking — retail footfall/in-store analytics, ALPR-adjacent Bluetooth/Wi-Fi trackers, and co-travel correlators — by fabricating a continuously-rotating crowd of plausible-but-fake BLE and Wi-Fi device identities around the user. A companion controller node ("Vigil") also passively watches for AirTag/SmartTag/Tile-class followers. It is the wiki's first captured hardware/physical-layer entry in the [[obfuscation]] mechanism family, alongside the existing all-software instances (AdNauseam, TrackMeNot, Nightshade, Glaze).

## What Simulacra does

**Threat addressed.** Passive RF trackers — retail Bluetooth/Wi-Fi footfall sensors, ALPR-adjacent add-ons, and co-travel correlators — build a location/identity picture from a device's ambient radio emissions without the device owner's cooperation, the physical-world analogue of the digital surveillance-pricing and browser-fingerprinting mechanisms this wiki otherwise documents.

**Mechanism.** Nodes (built on off-the-shelf ESP32 boards, ~$20-50 each) continuously emit a rotating population of fake BLE/Wi-Fi device identities — realistic MACs, vendor/format shapes, advertising cadence — each capped at 15 minutes on-air, matching real-phone randomised-address rotation intervals. A self-learning engine harvests the *structure* of real nearby device adverts (never captured identity) to generate new decoy archetypes, gated against ever emitting protected identity subtypes (e.g. Apple Continuity / Fast Pair beacons). Multiple nodes coordinate over an authenticated, encrypted ESP-NOW mesh so the fleet reads as one diverse crowd rather than obviously-cloned decoys.

**Self-documented structural limit.** The README states directly that the tool cannot hide a device that already carries a persistent identifier: a trivial "any identifier seen on more than one day" filter defeats the entire fleet in a fixed-location long-term-observation scenario, because every Simulacra-emitted identity dies within 15 minutes. The project frames this as the deliberate, non-negotiable cost of the rotation-ceiling design, not a bug to be fixed by extending identifier lifetime. This is an independent, physical-layer confirmation of the same "blending in" paradox [[browser-fingerprinting]] documents on the digital side — Venugopalan et al. 2024 (FP-Inconsistent) show naive per-attribute rotation is defeated at ~97% true-negative-rate via cross-attribute inconsistency detection. Both findings converge on the same conclusion: rotation alone, without matching the joint statistical structure of real devices, is a leaky defence — Simulacra's answer is structure-only learning from ambient captures rather than hardcoded archetypes, audited by a host-side test suite (`decoy_audit`, `probe_audit`, `radar_audit`) that scores separability against real-world captures.

**Security model.** Asymmetric by design: the controller node holds the private Ed25519 signing key, decoys hold only the public key, so a captured decoy cannot forge fleet commands. Starter (web-flashed) builds ship with no control plane at all, since anything compiled into a public binary is public; real fleet control requires a self-generated keypair in the "provisioned" build path. The shared fleet-transport key (distinct from the control-signing key) is not encrypted at rest on-device, so a physically recovered decoy's key is recoverable — the project's documented mitigation is immediate fleet-wide revocation and re-keying.

**Actionability.** Lowest-friction entry point of any hardware privacy tool this wiki has captured: a browser-based web-flasher (ESP Web Tools/Web Serial, desktop Chrome/Edge) flashes a starter fleet with no toolchain or command line. A minimal build is one ESP32-C5 board plus one display-equipped controller board, no soldering required.
